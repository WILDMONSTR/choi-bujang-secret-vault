## 1. 프로젝트와 시연 범위

겨울철방어는 로그인 계정·기기·세션, 업무 접근 판정, 보안 기록·XDR 경보, AI 연결과 근거 설명, 요청/조치 상태 등을 별도 원천·확인 수준으로 보여 주는 **로컬 학생 보안 Agent**다.

제공되는 `내 PC 상태` 수집 기능을 중복 구현하지 않고 학생 영역에서 시각화했다. 학생 대시보드 안에서 ① 기능 점검표, ② 내 PC 상태, ③ 연결과 기록, ④ 내 앱·다시 조회 **네 개의 카드를 먼저** 표시한다. 그 아래에는 직전 두 실측의 변화량, CPU·메모리 SVG 추이 그래프, 이 브라우저 화면의 최대 8회 측정 기록이 나온다. **보호 현황 페이지 전체의 최상단에 카드 네 개를 강제로 배치한다는 조건은 아니다.** 제공 공통 화면은 그대로 유지한다.

Windows System·Application의 경고·오류 건수는 **침해 또는 공격 탐지 결과가 아니다**. PC 조회가 성공해도 SDP·AI·XDR 접속 성공을 의미하지 않는다.

## 3. 핵심 기능 3가지 — 실제 시연 순서

### 시연 1 — 내 PC 상태와 실측 추이

**위치:** 브라우저 `http://127.0.0.1:5189/` → **보호 현황 → 학생 상태·알림 표시 → 겨울철방어 · 개인 관제 대시보드**

1. 학생 대시보드 안의 4개 상태 카드를 보여 준다. `내 PC 상태`가 **공식 수집기 재사용**이고 진행 막대·추이는 **학생이 추가한 표시**라는 점을 설명한다.
2. `다시 조회` 클릭(또는 **Tab → Enter/Space**) → 조회 중 표시 → 성공한 CPU %, 메모리 사용/총량 GB, 디스크 여유/총량 GB, **각 값의 실측 시각**을 보여 준다.
3. **측정 시각이 달라지도록** 두 번째 `다시 조회` → CPU·메모리 그래프 카드, CPU 변화량(%p)·메모리 변화량(GB), 최대 8개 과거 기록을 보여 준다.

**통과 판단:** 검증된 실제 응답에만 진행 막대와 그래프 점이 있다. 조회가 한 번뿐이면 그래프의 유효한 두 점 비교가 불가능하다고 표시된다. 실패 항목은 `확인 불가`와 사유로 표시하며 임의 숫자·예시 그래프를 정상처럼 보여 주지 않는다. 과거 실측은 **현재 실측과 별개**임을 명시한다.

**증거:** `student/extension.mjs` 코드 확인 및 [GitHub Actions 모의 DOM/API 테스트 성공](https://github.com/WILDMONSTR/choi-bujang-secret-vault/actions/runs/41415873878). 사용자 Windows PC의 최종 그래프 화면 **미확인**. 숫자는 실제 시연 때 나온 값만 해당 PC에서 기록한다.

### 시연 2 — PC 네트워크·방화벽·Windows 기록

**위치:** **보호 현황 → 공식 내 PC 상태 / 학생 연결과 기록 카드**

1. 네트워크 인터페이스 개수·IPv4 구성 요약과 측정 시각을 확인한다.
2. Windows 방화벽 **Domain / Private / Public** 프로필을 **읽기 전용**으로 확인한다.
3. **최근 24시간 Windows System·Application 경고·오류 건수**와 집계 상한·제한 여부를 확인하고, **이 건수는 공격 탐지 결과가 아님**을 읽어 준다. 로컬 PC 조회 결과와 **SDP 연결 여부**도 별도로 보여 준다.

**통과 판단:** 읽지 못한 항목은 관리자 권한을 요구·획득하지 않고 `확인 불가`와 이유로 남겨 둔다. SDP 실제 연결을 검증하지 못했다면 `SDP 미연결` 또는 `연결 확인 불가`로 분리한다.

**증거:** `src/pc-status.mjs`, `public/pc-status-view.mjs`, `student/extension.mjs` 코드 확인. 사용자 PC에서 관측한 네트워크·방화벽 상태 및 실제 Windows 경고·오류 **건수는 미확인**.

### 시연 3 — 신원·AI 연결 및 보안 기록

**위치:** **보호 현황 → 계정·기기·세션 / AI 연결**, 이어 **업무 앱 → 보안 기록**

1. 현재 계정·기기·세션을 보여 준다. ALEPH 계정 연결 성공과 **AI 앱 승인 성공을 구분**한다.
2. **AI 연결 점검** 결과를 별도 확인한다. **사용자가 계정 연결·AI 연결·AI 연결 점검 모두 성공했다고 보고했으며**, 이를 실제 화면 캡처나 실행 로그를 제출받았다고 표현하지 않는다.
3. 업무 접근 판정과 보안 기록·XDR 사건은 **현재 조회된 원천·근거가 있을 때만** 보여 준다. 연결 없음·확인 불가·예제 모드라면 그 상태를 그대로 설명한다. 보안 조치 효과를 검증 없이 `성공`으로 발표하지 않는다.

**통과 판단:** 계정·AI 연결 성공을 SDP·XDR 원천 접속, 실제 침해 탐지 또는 AI 사건 설명 성공으로 확장해 말하지 않는다.

**증거:** 학생 8개 렌더러 원문 확인. **계정·AI·API 점검 성공은 사용자 보고**이며, 원천 SDP·XDR 실연결과 실제 AI 사건 설명·보안 조치 결과는 별도 검증 대상이다.

## 5. Git·NPM 없이 같은 소스를 실행하는 방법 (Windows)

**기본 방법:** [GitHub `main` ZIP 다운로드](https://github.com/WILDMONSTR/choi-bujang-secret-vault/archive/refs/heads/main.zip) → 기존 프로젝트·제출물을 지우거나 옮기지 않고 **새 위치**에 압축 해제 → 새 `on-client` 폴더에서 **일반 사용자 PowerShell** 실행.

```powershell
# PowerShell의 현재 위치가 새로 받은 on-client 폴더인지 확인
Get-Location
node --version
node -p "require('./package.json').version"
node --check .\student\extension.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

정상적으로 앱이 켜지면 `http://127.0.0.1:5189/`에 접속한다. **시연 1 → 시연 2 → 시연 3** 순서로 진행한다. 서버 종료는 실행 중인 PowerShell 창에서 **Ctrl+C**. 재시작 후 그래프 기록이 이전 실행에서 자동으로 이어진다고 주장하지 않는다.

**참고:** 새 폴더에서 계정·AI 연결은 다시 확인해야 할 수 있다. 기존 연결 성공 폴더·개인 설정은 보존하되 비밀 파일을 GitHub나 보고서에 올리지 않는다. 공식 기능이 없거나 조회에 실패하면 그대로 `확인 불가` 또는 `미연결`로 보고한다.

**포장 금지:** `npm run package-app` 또는 새 포장 스크립트를 실행·작성하지 않는다. `node --check`는 문법 검사일 뿐 동작 성공을 증명하지 않는다.

- 저장소: https://github.com/WILDMONSTR/choi-bujang-secret-vault
- **작성 전 기준 커밋:** `bb84b0978d0aeccb156dcc42ac769fdf40e88100`.

Git이 없는 ZIP에는 `.git`이 없으므로 로컬 `git rev-parse HEAD`를 실행할 수 없다. 대신 **GitHub 커밋 화면의 실제 40자리 SHA**와 다운로드한 ZIP의 기준 커밋을 비교한다. Git이 있는 PC에서만 `git status --short`, `git diff --stat`, 필요한 파일만 `git add`, `git commit`, `git push`, `git rev-parse HEAD` 순서로 검증한다. push가 거절돼도 `--force`로 덮어쓰지 않는다.

**최종 상태 표현:** 0.2.21 소스 구현·GitHub 반영·모의 테스트는 검증됨. **실제 Windows 브라우저 전체 시연, 사용자 PC 실측 자료, SDP·XDR 원천 및 공식 판정은 별도 확인 필요.**
